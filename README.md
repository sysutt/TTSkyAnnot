# TTSkyAnnot · 星图查看与标注

一个独立的小工具：快速查看天文图像，自动解析星场，标注深空天体和恒星，不需要 PixInsight。

A small standalone tool to view astronomical images, plate-solve them and annotate deep-sky objects and stars,
without PixInsight. English summary below.

## 能做什么

**查看**
- 打开 FITS、XISF、TIFF、JPEG、PNG。可以直接拖进窗口，也可以在资源管理器里右键用「打开方式」选择 TTSkyAnnot。
- 线性数据（叠加母版）按 PixInsight 的自动屏幕拉伸（STF）显示，可切换「联动」「分通道」「不拉伸」。
  PNG、JPG 这类已经成品化的图片**一律按原样显示、不做任何拉伸**。
- 「L」打开**直方图面板**：每个像素一列的 RGB 柱状图、16 位坐标轴、可缩放的曲线、和画面同一套黑/白/中间调。
- 滚轮缩放，拖动平移，「F」适应窗口，「1」原始大小，左右方向键切换同一文件夹里的上一张、下一张。
- **切换图片会保留当前的缩放和位置**（同尺寸的图之间），方便对着同一处细节比较两张的差别；换到尺寸不同的图
  则自动适应窗口。
- 还没打开图片时，点一下主界面就会弹出文件选择窗口；打开后左边列出同目录下的其他图片，点一条即可查看。
  上一张、下一张、播放都在画面底部的操作栏里，画面上不再有悬浮按钮挡着。
- 同目录里跟拍生成的低分辨率**缩略图**（如 ASIAIR 的 `*_thn.jpg`，244×160）不会进列表：名字里带 `_thn` 的在建列表
  时就按文件名跳过（不读任何文件头，列表从第一帧起就是干净的）；其余预览图再按尺寸判断——长边不到同目录最大图片
  1/4 的视为预览图跳过。上一张、下一张和自动播放也一并跳过它们。尺寸判断在后台线程里做，慢盘上不会卡住窗口。
- 打开速度：一张 2600 万像素的 FITS 首次大约 2–3 秒（再看同一张、或系统已缓存该文件时更快）。显示用的 8 位图
  由**每个通道一张 65536 项的查找表**生成——白平衡和拉伸都是一条曲线，整幅只需一次查表，不必为屏幕做十几遍
  全幅浮点运算；缩放后的屏幕图也用 Pillow 的 BOX 平均一次算好，窗口不会在图片出现后再卡一下。
- 在文件名列表里点右键，可以在文件资源管理器中定位该文件，或复制它的完整路径／所在文件夹路径（左侧「文件夹」
  列表和右侧「标注」队列都支持）。- 工具栏「播放」（空格键）会自动轮播当前目录下的所有图片，到头绕回第一张；再点一下（或按空格）暂停。
  每张停留的秒数在「设置 → 自动播放间隔」里改。
- 画面底部有一条**操作栏**：上一张 / 播放 / 下一张，然后是筛选用的**删除**和**移动**。删除只是把文件送进
  回收站（不是直接抹掉），状态栏会给出一段时间的 Ctrl+Z 撤销；如果该磁盘没有回收站，会明说"无法撤销"。
  移动会把当前图片放进你选的文件夹，同样可以撤销。工具栏的「图像操作栏」可以整条隐藏。
- 鼠标处显示像素原始数值；已解析的图同时显示赤经、赤纬。
- 「H」查看文件头：FITS 关键字和 XISF 属性。
- 已经带解析结果的图，打开就叠加显示深空天体和亮星，不联网、不等待。

**解析与标注**（「解析并标注」，可以一次选多张）
1. 本机提取星点 → 在线粗解（只发送星点坐标）→ 用 Gaia DR3 精修，带畸变修正（TAN-SIP）。
   在线粗解不成功时，依次改用 ASTAP（需自行安装）和 nova.astrometry.net（需在设置里填 API key）。
2. **解析本身不写任何文件。** 每张解析完成后会弹出确认框，逐项勾选要写什么（天体列表、轮廓坐标、标注预览图、
   写回图片），不勾的就不写；也可以整张跳过，解析结果留在窗口里继续看。批量处理时勾一下「以后都按这次的选择
   保存」就不再逐张询问。跳过的结果之后可以随时用「保存当前结果」补写。
3. 右栏「星表」可以挑参与解析的星表（Hipparcos / Tycho-2 / Gaia DR3），也可以「全选」「清空」。**没勾的
   星表根本不会去查询**，所以只留 Gaia 就只等 Gaia 一次查询。捆绑的亮星表（NamedStars）不需要查询，始终写出。
   命令行用 `--cats hip,gaia` 指定。
4. 输出：
   - `<图名>.objects.txt`：和 PixInsight AnnotateImage「Write objects to a text file」格式一致，包括亮星名、Messier、NGC-IC、Sharpless，以及上一步勾选的 Hipparcos、Tycho-2、Gaia DR3（默认 16 等以内）；
   - `<图名>.annotated.jpg`：标注预览图；
   - `<图名>.outlines.json`：每个天体轮廓的像素坐标；
   - 解析结果写回原图：FITS/XISF 写进文件头，像素和其他内容原样不动；JPG/PNG/TIFF 另存同名 `.wcs` 文件。
5. 右栏「在 PixInsight 中打开」把当前这张原图交给 PixInsight（和资源管理器里「打开方式 → PixInsight」同一
   条命令，走它的单实例机制，原文件不做任何改动）。找不到 PixInsight 时可以在「设置 → PixInsight 路径」
   里手动指定。

**精度**：以图上实测的星点质心为准，在拍摄历元下比较。

| 图像 | PixInsight | TTSkyAnnot |
|---|---|---|
| M33，每像素 1.08″ | 中位 0.23 px | 中位 0.13 px |
| M1，每像素 0.29″ | 中位 0.35 px | 中位 0.35 px |

复测方法见 `tests/accuracy_vs_pi.py`。窗口的打开方式、目录列表和上一张/下一张按钮可以用
`python tests/gui_smoke.py` 无窗口自检（不需要显示器）。

**和 PixInsight 导出的 TXT 有哪些不同**

- **像素坐标按拍摄日期的星位计算**，标出的是照片里星星实际所在的位置；PixInsight 投影的是 J2000 星位，自行大的星会偏开，在每像素 0.3″ 的图上约 1 像素。赤经、赤纬两列和 PixInsight 一样，仍写 J2000。
- **NGC/IC 用 OpenNGC 的现代坐标**，比 PixInsight 用的 NGC 2000.0 更准，所以有些天体位置、星等、直径会和 PixInsight 不同。
- **Gaia 块的 Flags 列留空**：那是 PixInsight 本地数据库的内部标志，VizieR 上没有。
- **亮星块**用耶鲁亮星表加 IAU 正式星名，不含 PixInsight 那些非正式俗名。

## 运行

```bash
pip install -r requirements.txt
python -m skyannot                       # 窗口
python -m skyannot image.xisf            # 打开指定图片
python -m skyannot --annotate *.fits     # 命令行批量处理,不开窗口
```

界面配色在「设置 → 界面配色」里用一个**开关**切换（只有两种状态，不需要下拉菜单）：**深色**（默认）和**浅色**
两套，共用 TTAstroRoom 的设计规范：一个品牌绿强调色、近黑深蓝灰系统底色、发丝级描边、小圆角、4px 间距栅格。
窗口自己的标题栏也跟着配色（深色模式下是深色标题栏、白色文字）；看图区周围的画布同样跟随主题（浅色模式是浅灰
画布，深色模式是近黑画布）。

配色**不需要重启**：所有随主题变化的规则都由配色生成成一份应用级样式表，拨动开关并关闭设置窗口后，窗口立刻
按新配色重画（标题栏、画布和自绘控件再单独刷新），选择同时写入设置文件。（界面**语言**仍然是重启后生效，保存
时会询问是否立即重启。）两套配色的文字对比度都按 WCAG AA 校准过（正文 ≥ 4.5:1）。

程序内的对话框（设置、文件头、保存结果、直方图）都不带系统标题栏：标题和**唯一的**关闭按钮由程序自己画，
拖标题栏可移动，右下角可调整大小，Esc 关闭。系统标题栏那套「? / ✕」不会再多出一个关闭按钮。

### 设置文件放在哪

**首选程序自己的目录**：`dist\TTSkyAnnot\config.json`。整个文件夹可以拷贝/移动到别的电脑，设置跟着一起走，
不需要用户配置目录；写不进去时（比如装在 `Program Files` 下这种只读位置）自动退回到
`%APPDATA%\TTSkyAnnot\config.json`，每个 Windows 用户各一份。从旧版本升级时，程序第一次启动会把 `%APPDATA%`
里的设置**复制**到程序目录，原来的文件保留不动。环境变量 `TTSKYANNOT_CONFIG` 可以指定任意路径（测试用）。

### 软件内更新

程序启动约 1.5 秒后会在后台读「设置 → 更新源」里的 `version.json`（默认是
`https://www.ttastro.com/ttskyannot/updates/`，也可以填网址、`\\服务器\共享` 或本地文件夹；留空则不检查）。
发现更高版本时弹出「软件更新」：当前版本 → 新版本、下载大小、更新说明，可以「稍后」（可勾
「跳过这个版本」，下次启动不再提示）或「立即更新」。状态栏右侧的「检查更新」随时可以手动查，有新版本时会变成
`↑ 0.2.2`。

「立即更新」的流程：

1. 把整包下载到临时目录，**校验 SHA-256**（与 `version.json` 里的一致才继续）；
2. 解压，找到包里的 `TTSkyAnnot.exe` 所在目录；
3. 写一个小的批处理，等本进程退出 → 把旧目录改名 `TTSkyAnnot.old` → 新目录就位 → **保留原来的
   `config.json`** → 启动新版本。批处理先 `cd` 到系统目录（在程序目录里运行它是改不了名的），并在 90 秒内
   反复重试（杀毒软件可能还会短暂占着刚退出的 exe）；确实换不了时会把旧版本重新启动，原因写在
   `update.log`（临时目录，通常是 `%TEMP%`）。新版本启动时会把 `TTSkyAnnot.old` 删掉。

**发布新版本**（改完代码之后，一条命令完成）：

```
powershell -File packaging\release.ps1                 # 版本号补丁 +1（0.2.1 → 0.2.2），全部流程
powershell -File packaging\release.ps1 -Bump minor -Notes "这次改了什么"
powershell -File packaging\release.ps1 -Version 0.2.3 -SkipBuild   # 只重新打包/上传已经构建好的版本
```

`release.ps1` 依次做：

1. 改 `skyannot\__init__.py` 的 `__version__`（`-Version` 可指定，默认 `-Bump patch`）；
2. PyInstaller 构建到 `dist_new`，`sign.ps1` 签名；
3. `publish.ps1` 打包成 `TTSkyAnnot-<版本>.zip`（不含 `config.json`）并写 `version.json`（version / url /
   sha256 / size / notes / built），旧的升级包只留最近 2 个；
4. **先传 zip、再传 version.json**（用 `scp` + 服务器上的 `sudo install`，更新源目录
   `/var/www/ttastro/ttskyannot/updates`），这样更新源永远不会指向一个还没传上去的包；
5. 从公网地址 `https://www.ttastro.com/ttskyannot/updates/` 取回 `version.json` 和 zip 的 `Content-Length`
   做校验，证明线上真的生效；
6. （新）用 Inno Setup 打一个 Windows 安装包 `TTSkyAnnot-Setup-<版本>.exe`，签名后和绿色包一起上传
   （`/ttskyannot/setup/`，另存一份固定名 `TTSkyAnnot-Setup.exe` 给网页的下载按钮）；
7. 把同一个构建装到本机 `dist\TTSkyAnnot`、重新签名，并把本机「更新源」设成公网地址；
8. 把源码提交并推送到 GitHub（`git add -A` + commit + push），再打一个 `v<版本>` 标签一起推上去；
   工作区里有超过 90 MB 的文件（比如误放进来的升级包）时这一步会拒绝提交并提示加进 `.gitignore`，
   推送失败（离线、没有密钥）只记为警告，提交留在本地。

服务器走本机已有的 ARM 密钥（`~\.ssh\ttastro_arm` → `ubuntu@168.138.200.230`），没有密钥时按站点项目的
HANDOFF 走 tickwhale 中转。本机不装服务器密钥的机器可以用 `-SkipUpload`，只生成本地包。

**安装版与绿色版**：网页上给两个入口——

- 安装版 `https://www.ttastro.com/ttskyannot/setup/TTSkyAnnot-Setup.exe`：Inno Setup 打的安装包，
  **默认按用户安装**（`%LOCALAPPDATA%\Programs\TTSkyAnnot`，不需要管理员），开始菜单里有「TTSkyAnnot 星图标注」，
  带卸载项；装在用户目录是为了让程序目录可写——`config.json` 就在旁边，软件内更新也要能改这个目录；
- 绿色版：`updates/TTSkyAnnot-<版本>.zip`，解压即用，设置同样在程序目录。

压缩包里有一份 `使用说明.txt`：最常见的启动失败是**没有完整解压**（缺少 `_internal`），或者杀毒软件隔离了里面的
Qt 文件；0.2.6 起程序会自己检测这种情况并弹出中文说明，而不是只报一行 `DLL load failed while importing QtCore`。

**介绍页**：`https://www.ttastro.com/ttskyannot/`，英文版 `https://www.ttastro.com/ttskyannot/en/`
（源码在站点项目的 `site\ttskyannot\`，复用了 `/assets/site.css` 与 `site.js` 的星空背景与滚动动效；两页互相
`hreflang` 指向，导航里的 EN / 中 按钮直接跳转到对应语言页）。改完页面用一条命令发布（中英文一起传）：

```
powershell -File packaging\deploy-page.ps1
```

页面本身会读取 `updates/version.json` 显示最新版本、大小和更新说明，所以发版后不用再改页面。


## 拉伸模式与自动白平衡

工具栏「拉伸」可选：

| 模式 | 做什么 |
|---|---|
| **自动**（默认） | 线性数据时选「自动白平衡」；已拉伸或 PNG/JPEG 则不拉伸 |
| **自动白平衡** | ASIFitsView 的显示流程：解拜耳 → 白平衡 → 一条曲线，见下 |
| 联动 | 三个通道用同一条曲线（PixInsight 的 STF） |
| 去底色 | 逐通道减掉各自天空底色，再统一拉伸 |
| 分通道 | 每个通道独立拉伸（会放大颜色差异） |
| 不拉伸 | 原样显示 |

**成品图不拉伸**：处理完的图（PixInsight 导出的 XISF、拉伸过的 FITS、JPEG/PNG）已经带好了曲线，再拉一次只会把
亮部打爆。程序在载入时判断数据是线性还是已拉伸——线性数据的天空是一个又窄又高的峰（MAD ≤ 中位数的 10%，
且没有真正的黑像素），拉伸过的图天空被拉宽了（M33 成品的 MAD/中位数是 0.22，线性单张是 0.02–0.04）。判为成品
后不论「拉伸」选的是哪一项，都按原样显示，状态栏标出「已拉伸」。

### 「自动白平衡」是怎么来的

ASIFitsView 会在 `%APPDATA%\ASIFitsView\log\` 写下**它每一步做了什么**，从中可以读出它的完整流程：

```
runDeBayer                    解拜耳
runAutoWhiteBalance           自动白平衡
getHistAfterAWB               取白平衡后的直方图
Hist Auto Stretch / Color Stretch    一条曲线作用于全部通道
autoStretch minValue: 1502, autoStretch midValue: 2317    黑点/中间调（16 位刻度）
```

所以它的顺序是**解拜耳 → 自动白平衡 → 一条联动曲线**（不是分通道）。本程序的「自动白平衡」按同样的顺序做：

1. **白平衡**：逐通道取平均，把红、蓝抬到绿的水平——ASI2600MC 这张 NGC 1499 单张是 R ×1.325、B ×1.349。
2. **天空底座**：白平衡只让三个通道的*平均*相等，单张照片的天空本身还会差一两个百分点；曲线一陡，这点差
   就是肉眼可见的色偏。于是再逐通道减掉各自天空的直方图众数（相减而不是再乘一次，星云自己的颜色不会被改写）。
3. **一条曲线**：用从它面板上读出的窗口——`黑点 = 三通道最小值均值 + 200`、`白点 = 黑点 + 815`（16 位刻度）——
   加一条中间调曲线作用于全部通道。这张图的窗口是 1482–2297。

这个固定宽度的窗口在大多数单张上都合适，但它**不是对所有帧都成立**：一张长曝光、高增益的单张（ASI294MC，天空
就落在 0.06）窗口会整个落在天空附近，画面里 47% 的像素被推到纯白——中间的天体自然也跟着"过曝"。所以窗口先按
上面的规则定，然后检查一次：**如果超过 1% 的像素落在白点之上，就把白点开到数据自身的高端**（逐通道 99.9 分位
再留 5% 余量，饱和星点除外）。这样天空仍然按 ASIFitsView 的锚点压暗，天体则留在窗口内，不会被拉成一片白。

一个关键前提：**解拜耳必须保住每个通道的均值**。旧的双线性实现把 2×2 格子里另一颜色的像素填进了红、蓝通道，
留下 1 像素的棋盘格，通道均值也被拉偏（红 +16%、蓝 +18%）。白平衡的增益是拿均值算的，于是算出的增益不对，
再乘回整幅图，天空就整片发紫。现在 `debayer.py` 只在同色像素之间插值：常数色块还原成常数色块，通道均值与
传感器读到的一致，白平衡才成立。

**和分通道的区别**：分通道把每个通道各自的中位数都压到 0.2，天空也能变中性，但星云的颜色关系被改写；
自动白平衡让天空中性、星云保持红 ≥ 蓝。

### 直方图面板（L 键）

按 ASIFitsView 的直方图重做：

- **每个像素一列的 RGB 柱状图**：红、绿、蓝各自填充，重叠处能看出三个通道的相对位置；横轴是 16 位 ADU，
  不是 0–1 的小数。图下面一行给出黑点、中间调、白点的 ADU 数值。
- **放大**：工具栏的放大镜按钮打开后，在图上拖一个框即可放大；滚轮以光标为中心缩放，拖动平移，双击回到默认
  窗口（拉伸窗口上下各留 35% 余量，所以打开面板看到的就是天空主峰，而不是挤在最左边的一根尖刺）。
  每次缩放都会**重新统计**当前范围的样本，所以放到多细都有一像素一柱的分辨率。
- **统计数据**：右侧是 Max / Min / Avg / Std 四行，R/G/B 三列用色块标出，数值是 16 位计数——布局和
  ASIFitsView 的统计面板一致，可以直接对着比。
- **和画面同一套数字**：打开面板时用的就是画面此刻的白平衡和拉伸；拖黑/白三角、或按「自动白平衡」「自动拉伸」
  「重置拉伸」，关掉面板后画面按同一组数字重画。面板从不改文件。
- **面板自身的窗口**：没有系统标题栏（标题和关闭按钮都是面板自己的，所以不会出现两个 ✕）；拖标题栏可以
  移动，右下角拖动可以改大小，Esc 关闭。

## 天体形状与缺失的位置角

「天体形状」有两个模式：**轮廓线**用 Stellarium 的真实轮廓（290 个天体），**圆圈**用星表尺寸画椭圆/圆。

**OpenNGC 有 2586 个天体没有 `PosAng`（位置角）**——几乎全是星云，包括 NGC1499。旧代码把缺失当成 `0°`，
于是画出一个**竖直椭圆**，等于凭空断言了一个星表从未给过的方向。

现在的规则：

| 情况 | 画成 |
|---|---|
| 星表有 `PosAng` | 按它画椭圆（原样，不改） |
| 没有，但有**明显拉长**的轮廓（长短轴比 ≥ 1.30） | **用轮廓自己的长轴**，短轴也取自轮廓 |
| 没有，轮廓是圆的（比 < 1.30） | **正圆**——圆的东西没有长轴，噪声不算方向 |
| 都没有 | **正圆** |

实测：NGC1499 从竖直（90°）变成 **约 33° 倾斜**，和它真实的走向一致。

### 标注文字的位置

名字先试着放在**天体自己里面**：像 NGC1499 这种画成大圆圈的目标，标题就落在圆心附近（只要字放得下、背景
够暗）；小目标放不下就回到轮廓（或星点）外侧。外侧的位置优先落在暗的背景上，并且躲开已经放下的标签和
坐标网格；被占了就往外让一档（4 档，每档 18 px），**实在没有空位就这一个名字不画**——宁可少一个名字，
也不把两个名字印在一起。NGC1499 的大标签和它边上 ksi Per 的星名就是典型例子。`.annotated.jpg` 预览图
用同一套规则。**缩放时标签跟着自己的天体走**：位置记下来按同一屏幕偏移重画，只有确实会撞上别的标签时
才重新找位置，所以名字不会在缩放时跳来跳去。

### 关于从外部数据补 PosAng

- **tickwhale 的 API 没有位置角字段**（只有 `size_major`/`size_minor`），补不了。
- SIMBAD / VizieR / HyperLEDA 在这个开发环境里解析到非公网地址，取不到。

能就地解决的只有「星表和轮廓都有」的那部分。因此位置角**不写进数据文件**，而是在画的时候从轮廓现算——
轮廓更新了它跟着更新，不会出现两份数据互相漂移。

### 从 HyperLEDA 补充位置角

`tools/leda_pa.py` 从 VizieR 的 **HyperLEDA（表 VII/237，98 万个星系）** 取位置角，写进
`data/openngc/posang.csv`（**243 个天体**）。

```bash
python tools/leda_pa.py --validate   # 下载、匹配、自检，不写文件
python tools/leda_pa.py --write      # 生成 data/openngc/posang.csv
```

**自检结果**：拿 OpenNGC 自己**已有**正角的 8635 条记录做基准，比对 HyperLEDA 的值 ——
**中位差 2.0°，83% 在 10° 内，92% 在 20° 内**。匹配方式优先用 PGC 编号（8313 条精确命中），
没有 PGC 时按位置匹配（容差 1 角分）。

**是独立文件，不改 `NGC.csv`**：上游星表保持原样，补丁可随时重新生成或删除；每条都带
`SepArcmin`（匹配偏移）和 `Source`（出处）便于核对。首次下载 45 MB，缓存在 `.leda_cache/`。

**为什么只有 243 个**：HyperLEDA 是**星系**表，而缺失正角的大多是星云和星团。剩下 2343 个里，
拉长的部分由轮廓长轴覆盖，圆形的本来就该画圆。

| 来源 | 能补的 | 精度 |
|---|---|---|
| HyperLEDA（星系） | 243 | 中位 2.0° |
| 轮廓长轴（拉长的天体） | 91 | 中位 10–14° |
| 都没有 | 其余 | 画正圆，不编方向 |

## 直方图面板

工具栏「直方图」（快捷键 `L`）打开，参照 ASIFitsView 的面板做的：

- 三个通道的直方图曲线 + 亮度曲线；
- **两个边界手柄**（黑点、白点）和**中间调手柄**，直接拖，画面实时跟着变；
- 右侧是要统计数据的 `Max / Min / Avg / Std`（按 16 位刻度，和 ASIFitsView 一致，方便对照）；
- 三个快捷动作：**自动白平衡**、**自动拉伸**、**重置拉伸**。

**只影响显示，不改文件。** 拉伸用的是 PixInsight 那套：先把黑点到白点归一化，再用一条**中间调曲线（MTF）** 把中间调推向亮或暗。关键是**三个通道共用同一条曲线**——这正是它能在拉伸的同时保住通道之间颜色关系的原因。

### 自动白平衡

和 ASIFitsView 一致：**不是压制绿色，而是把红、蓝增强到绿色的水平**（实测其面板：关闭时 1259/1669/1236，开启后 1668/1669/1669；本程序按 增益 = 绿均值/各通道均值 实现，绿通道增益恒为 1）。

### 为什么这个面板对你有用

之前颜色调不准，是因为缺少一个能**直接反推**的观测量。现在你可以把鼠标放在画面纯天空处、拖动黑点直到天空变成你想要的暗度——**天空的 RGB 由你定，不用猜它的算法**。

## 缩放时的条纹网格

图像缩小到约 14% 时，天空会出现规则的条纹网格。**不是解拜耳的问题**——1:1 裁切和数据频谱都干净：

| 检查 | 结果 |
|---|---|
| 1:1 裁切 | 正常星点与噪声，无网格 |
| 数据里的周期成分 | period 3 仅 **0.1%**，偶周期约 3%（拜耳残留） |
| 用 LANCZOS 降采样 | 自相关**无峰**，标准差 8.4 |
| 用 Qt 缩到 14% | 自相关**每 3 像素一个峰**，标准差 29 |

原因是 **Qt 的平滑缩放采样**：6248 像素缩到 14%，每个目标像素只取七个源像素之一；画面里那 3% 的
2 像素残留与采样网格拍频，就成了一张条纹网。

修法是**先按缩放级别做面积平均（box filter）再交给 Qt**，Qt 只需处理不超过 2 倍的倍率：

- 显示分辨率随缩放级别重选（`_rebuild_pixmap`，120 ms 防抖）
- 场景坐标仍是整幅图像尺寸，标注位置不受影响
- **放大时不平均**：1:1 及以上始终显示原始像素

效果：自相关峰消失，标准差 29 → 8。

## 彩色图像与解拜耳

单次彩色相机（OSC）的原始帧是**单通道的马赛克**：每个像素只透过红、绿或蓝一种滤镜，直接显示是灰白格纹。
打开这类图像时会**自动解拜耳**成三通道再显示，状态栏会写明 `彩色 RGGB → 已解拜耳`。

判定看两件事，缺一不可：

- **数据结构**：已经是三通道就不是马赛克（PixInsight 输出的 RGB 图仍会残留 `BAYERPAT` 关键字）；
- **文件头**：`BAYERPAT` / `BAYERPATTERN` / `PCL:CFASourcePattern` 给出模式。另外，如果文件记录了
  `PCL:CFASourceFilePath`（它的 CFA 来自哪个文件），说明这张**已经解过**，不再重复插值。

插值用双线性：不会凭空造出数据里没有的颜色，在短曝光的噪声上也稳定，**而且不是最终处理步骤**——真正的
处理仍然交给 PixInsight。算法保证每个像素在它自己的通道上**取原值不插值**（125 项测试里有 4 项专门验证这点，
四种拜耳排列都测）。

「设置 → 解拜耳」可以关掉，用于查看原始马赛克数据。

### 手动指定拜耳阵列

如果文件头**没写** `BAYERPAT`（或者写错了），右栏「拜耳阵列」可以手动指定。传感器实际只可能是这四种排列
（每种两个绿像素，分在两条对角线上）：

![拜耳阵列](.skyannot_shots/bayer_patterns.png)

| 排列 | 2×2 单元（左上起） |
|---|---|
| `RGGB` | 红 绿 / 绿 蓝 |
| `BGGR` | 蓝 绿 / 绿 红 |
| `GRBG` | 绿 红 / 蓝 绿 |
| `GBRG` | 绿 蓝 / 红 绿 |

R/G/G/B 一共 24 种排列，但**只有这 4 种是物理上存在的**（两个绿必须落在不同行列），所以只列这四种——
选错的代价是红蓝互换，比不选更糟。

这个选项**只对单通道的未解拜耳帧生效**：

- 三通道的 RGB 图 → 选项置灰，绝不重新解释已有的颜色
- 记录了 CFA 来源的帧（已解过拜耳）→ 同样置灰
- 文件头写了 `BAYERPAT` → **以文件头为准**，手动选择不会覆盖它（要改就改文件头）
- 单通道且文件头没写 → 可以指定；指定后立即重新读取并解出彩色

默认是「自动（按文件头）」。

实测性能：6224×4168 的帧约 **2.1 秒**、峰值内存约 300MB。

## 删除与移动

删除（`Delete` 键或底部 ✖ 按钮）会**先弹确认框**，框里显示的是**文件名**——筛图时最常见的误操作是删掉了相邻
那一张，只有文件名能让你发现。确认按钮写的是「移入回收站」而不是「确定」，默认按钮是**取消**，所以直接回车是
保留文件、不是删除。

删完仍会移到回收站并给出一段可撤销时间（`Ctrl+Z`）；如果该盘没有回收站，状态栏会写明"无法撤销"。

批量筛图嫌确认框烦，可在「设置 → 删除确认」关掉（关掉后按删除键直接移入回收站，仍可撤销）。

「撤销删除或移动」按钮把上一步的删除/移动还原。

## 标注内容：按星表分组

「标注内容」的开关是**星表**，不是天体类型——按星表检索才是观测者读这类清单的方式，而且在线库的 `type`
字段不可信（`Cr399`/`Mel111`/`Tr2`/`Stock2`/`King11` 在库里全被标成行星状星云，实际是疏散星团），所以按编号
（星表）分比按类型分可靠。

**降级去重**：一个天体可能同时属于多个星表（M31 也是 NGC224，NGC7000 也是 Sh2-117），它只会列在**按下面顺序
第一个勾选的**星表里，不会重复标注，计数也不会重复：

```
Messier → NGC → IC → Sharpless → LBN → LDN → VdB → Ced → RCW
```

例如关掉 Messier，M31 会自动落到 NGC 里继续标注；关掉 NGC 和 IC，只属于它们的 Sharpless 星云就不标了。

**本地数据**（离线，始终可用）：Messier 109、NGC 8098、IC 5211、Sharpless 313，来自 OpenNGC 与 VizieR。

**在线数据**（在「设置 → 在线天体库」填地址后可用）：LBN、LDN、VdB、Ced、RCW。这些本地没有，按椭圆绘制。

**「亮星名」和「坐标网格」是需要的**，但不属于星表，所以单独一组开关放在星表下面，**默认开启**。亮星名来自捆绑的
耶鲁亮星表（按拜耳编号标注所在视场内的亮星），坐标网格按当前解析结果画赤经赤纬刻度。这两个开关的状态和其它
选项一样会记住。

叠加图的**颜色仍按天体类型**（星云青、星系玫瑰、星团金），这是按"标注压在什么上面"选的：星云在照片里多为
红/粉色，故用互补的青；星系是黄白色，故用玫瑰色。

## 解析器

按顺序尝试：**ttastro.com**（只上传星点坐标）→ **ASTAP**（离线，需本机安装）→ **nova.astrometry.net**
（需 API key）。任一个成功即可。

### 在线解析密钥（可选）

ttastro.com 的在线解析对**匿名请求**只留很小的额度（每天 20 次，按 IP 计），批量解析请领一个免费密钥：

1. 打开 <https://www.ttastro.com/ttskyannot/key>，用邀请码或 GitHub 登录领取；
2. 把密钥填进「设置 → 在线解析密钥（可选）」，确定；
3. 之后解析请求会带 `X-API-Key`，额度是**每小时 150 次、每天 600 次**。

密钥保存在程序目录的 `config.json`（`api_key` 字段），换电脑时连同文件夹一起拷走即可。密钥无效或过期时
在线解析会返回 401，额度用完返回 429 并提示去领密钥——这两种情况都可以直接改走本机 ASTAP。

### 优先复用文件里已有的解

ASIAIR、NINA、PixInsight 在拍摄或处理时通常已经把**完整的天体测量解**写进文件头（`CTYPE1/2`、`CRVAL1/2`、
`CD1_1..CD2_2`，以及 SIP 的 `A_*`/`B_*` 系数）。有这样的解时**不再重新解析**，直接使用——省掉整轮解析等待。

但头里的解不会盲目相信，会先和画面里**实际检测到的星点**核对：把星表里的亮星按这个解投影到画面上，看
有多少颗落在检测到的星点附近。

| 判定 | 结果 |
|---|---|
| ≥3 颗亮星落在容差内 | 采用 |
| 只有 1 颗星，但距离亚像素 | 采用（宽视场里可能就一两颗亮星，而错解不可能让星表星落在 1 像素内） |
| 星点对不上 | **放弃，改用解析器**（过期的头比没有头更糟） |
| 星点少于 8 个、无法核对 | 放弃，改用解析器 |

「设置 → 复用文件头里的解」可以关掉。日志会写明用的是哪个（`solver: header`）。

### 用 ASTAP 离线解析

1. 「设置 → ASTAP 路径」填 `astap.exe` 的**完整文件路径**（不是文件夹），例如
   `E:\Program Files\astap\astap.exe`。
2. **必须再装一个星表数据库**（ASTAP 的星表是单独下载的，默认只带 D80）：

   | 焦距 / 视场 | 需要下载的星表 |
   |---|---|
   | 长焦，视场小于约 0.6° | **H17 或 H18** |
   | 视场 0.6°–6° | D80（安装包自带） |
   | 视场更大 | D50 / D20 / D05 |

   以 2170 mm + 2.9 µm 像素为例，视场只有 0.28°×0.15°，**只有 D80 是解不出来的**——星表分辨率不够。
   下载后把所有 `h18_*.1476` 文件放进 `astap.exe` 所在目录即可。

解析失败时程序会把 ASTAP 自己的输出和星表诊断写进日志（例如「只装了 D80，这个视场需要 H17/H18」），
不再只说一句「解析失败」。

### 修正文件头（焦距 / 指向）

有些帧的文件头带着**另一套设备**的参数（比如广角相机里留着长焦镜头的 `FOCALLEN=491`），或者干脆没写指向。
像素尺度是解析器的搜索依据：焦距错一个数量级，ASTAP 就会按错的视场去找星表，报「视场太小、需要 H17/H18」。

工具栏「修正文件头」可以改掉这两项：

- **焦距**（mm）、**像素尺寸**（µm）：下面实时显示它们换算出的像素尺度和视场，改完一眼能看出是否合理。
- **画面中心**：赤经/赤纬，时分秒 / 度分秒（与右栏「中心坐标」同样的格式），可以留空只改光学参数。
- 点「写入文件」后写回 `FOCALLEN`、`XPIXSZ/YPIXSZ`、`RA/DEC`（度数）和 `OBJCTRA/OBJCTDEC`（时分秒），
  已有 WCS 的帧还会同步 `CRVAL1/2`；文件通过临时副本原子替换，写一半不会留下坏文件。
- **批量**：勾上「应用到整个文件夹」，同样的值会写进这个文件夹里的每一张 FITS（缩略图不算），
  带进度条、可随时取消；某一张写不进去（被占用、只读）只记失败，其余继续，最后把失败数写进日志。
- 写完后这次的解析（以及之后的每次）都用新值：广角那帧从 1.95″/px（2.2°×1.5°）改成 62 mm 的 15.40″/px
  （17.7°×12.1°）后，ASTAP 1 秒即解出，尺度 15.44″/px。


## 天体名输入

右栏「天体名」可以直接搜索天体并在列表里选：

- **本地星表**（离线，始终可用）：OpenNGC 的 NGC/IC/Messier 及增补（Melotte、PGC、Caldwell、Barnard…）、
  Sharpless 亮星表。共约 1.37 万个天体，任意叫法都能搜到（`m57`、`ngc6720`、`ring`、`6720` 同一条）。
- **在线天体库**（可选，在「设置 → 在线天体库」填地址）：默认 `https://app.tickwhale.com`，用的是 tickwhale
  的 `dso_search` 接口，**不需要 API key**。它包含本地星表没有的深空星表（LBN、LDN 等）。填上空即启用，留空
  则只查本地。
  在线结果会随输入实时补进候选列表（防抖 220ms，在后台线程查询，慢或不通都不会卡住打字）。

选中一个天体后，解析用的提示坐标改用它在星表里的**真实位置**，比文件头里的指向可靠——挂载记录的"指向"是它
被命令对准的目标，不一定等于画面中心。

### 直接输入 RA / DEC

右栏「天体名」下面的「中心坐标」可以直接写画面中心的赤经/赤纬，**优先于天体名**作为解析提示（两个求解器都
拿它当搜索中心，能提高成功率、缩短搜索）：

- 赤经按时 分 秒、赤纬按度 分 秒写：`05 34 31.9 +22 00 52`。
- 分隔符随意：`05:34:31.9 +22:00:52`、`05h34m31.9s +22d00m52s`、`0h42m44s +41 16 09` 都行；
  也接受十进制度（`83.633 +22.014`），但**显示永远归一成时 分 秒 / 度 分 秒**，不会留在小数形式。
- 离开输入框时自动归一化并写进日志（`使用画面中心坐标 RA 05h34m31.90s Dec +22°00′52.0″`）；
  认不出来的文字（比如误把天体名写在这里）会标红边框并在日志里说明。

### 首次运行的安全提示

Windows 对**未签名**的本地 exe 可能弹「无法验证发布者」。本机已经处理了两件事：

1. **协议区域**：这台机器的 Internet 选项里 `file:` 协议被划到了 Internet 区，于是资源管理器对任何未签名的
   本地 exe 都先问一句。已把当前用户的该项改回本机区，原值备份在 `packaging\zone-file-backup.txt`（想恢复按
   文件里那行命令即可）。重启资源管理器或重新登录后生效。
2. **代码签名**：用本地自签名证书给两个 exe 签名，证书的公开部分已加入当前用户的「受信任的根证书颁发机构」
   和「受信任的发布者」，所以 Windows 现在会把它当作有发布者的程序。`packaging\build.bat` 每次构建后自动
   重新签名（`packaging\sign.ps1`）；在新机器上第一次用，先跑一次
   `powershell -File packaging\sign.ps1 -Create` 生成证书。

这套信任只在**这台机器、这个 Windows 账户**有效：把 `dist\TTSkyAnnot` 拷到别人的电脑上仍会提示「未知发布者」。
要分发给其他人，需要购买正式的代码签名证书（EV 证书还能立即获得 SmartScreen 信誉）。

## English

- **View** FITS, XISF, TIFF, JPEG and PNG: automatic screen stretch for linear data (linked / per channel),
  zoom and pan, raw pixel values and RA/Dec under the cursor, header table, previous/next image in the folder,
  and instant deep-sky overlay for images that already carry a solution.
- **Histogram panel** (`L`): one pixel-wide bar per value for R, G and B on a 16-bit axis, zoom (magnifier
  box, wheel, drag to pan, double click to reset) and the Max/Min/Avg/Std table beside it, laid out like
  ASIFitsView's. The black/white markers are the stretch actually on screen.
- **Auto white balance** in ASIFitsView's order — debayer, raise red and blue to green, take out each channel's
  sky pedestal, then one curve for all three — so an uncalibrated one-shot colour frame shows a neutral sky
  instead of a green or magenta one.
- **Solve and annotate**: local star detection, online rough solve (only star coordinates are sent; ASTAP and
  nova.astrometry.net as fallbacks), then a TAN-SIP refinement against Gaia DR3 that matches PixInsight's
  accuracy (table above).
- **Outputs**: a PixInsight AnnotateImage-compatible object list, an annotated preview, outline polygons in
  pixel coordinates (JSON), and the solution written back into the FITS/XISF header (pixels untouched) or a
  sidecar `.wcs` file.
- Pixel positions use the star positions at the observation date, so they match the picture; the RA/Dec
  columns stay J2000 like PixInsight's.
